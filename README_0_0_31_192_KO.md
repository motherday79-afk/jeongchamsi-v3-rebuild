# JCS 0.0.31.192 · AI PANEL 경량 게시 핫픽스

## 적용 기준
- 31.191 ONECLICK_PUBLISH_PATCH 적용 후 덮어쓰기
- 기존 파일 전체 삭제 금지
- 이 ZIP 내부 파일만 동일 경로에 덮어쓰기

## 수정 이유
AI/HUMAN 결과와 1,000개 응답은 정상 저장됐지만, 메인 게시 시 큰 RUN JSON 전체를 Redis에 다시 쓰면서 저장소 요청이 5초 내 끝나지 않는 경우가 발생했습니다.

## 변경
- 게시 시 전체 RUN 재저장 제거
- 기존 RUN 데이터는 그대로 보존
- 게시 상태/LOCK/게시시간과 메인 노출용 요약만 별도 publication 레코드로 저장
- 같은 게시 버튼 재시도는 idempotent 처리: 이미 게시 마커가 저장됐다면 성공으로 응답
- 기존 방식으로 이미 게시된 과거 RUN도 그대로 인식
- 공개 목록/상세/패널 이력은 새 publication 레코드와 기존 게시 RUN 모두 호환

## 기대 동작
1. HUMAN/AI 결과가 이미 저장된 현재 화면에서 `메인에 재게시` 클릭
2. 서버는 큰 1,000명 RUN을 다시 쓰지 않음
3. 약 수 KB 규모의 게시 마커/요약만 저장
4. 메인에서 해당 RUN을 최신 게시본으로 인식

AI/HUMAN 자료나 통합 JSON을 다시 올릴 필요가 없습니다.
