# JCS 0.0.31.153 — 정치인 상세페이지 진입 대기 감소

## 확인한 지연 구조

기존 화면은 로그인 상태 확인 → 즐겨찾기 조회 → 정치인 상세 요청을 순차 실행했습니다.
서버는 사진 조회가 끝난 뒤 분석 조회를 시작했고,
한 상세 응답 안에서 같은 정치인 프로필 목록을 여러 번 다시 읽었습니다.
상세 분석의 게시 스냅샷과 개인별 게시 정보를 가져오는 요청도 순차 처리했습니다.

최근 어느 배포에서 사용자 체감 속도가 달라졌는지는 확정하지 않았습니다.
이번 수정은 현재 코드에서 확인하고 재현한 불필요한 대기와 중복 조회를 대상으로 합니다.

## 변경

- 상세 API 요청을 로그인 확인과 함께 시작합니다. 즐겨찾기도 기존 권한 확인 후 조회합니다.
- 받은 상세 결과를 화면에 전달해 중복 요청하지 않습니다.
- 서버의 사진·프로필·분석·권한 조회와 독립적인 게시 정보 조회를 병렬 처리합니다.
- 같은 HTTP 요청 안에서 같은 저장 키를 읽으면 진행 중이거나 완료된 GET을 재사용합니다.
  이 메모리는 요청 사이에 공유하지 않으며 Redis에 새 캐시 데이터를 저장하지 않습니다.
- 읽기 실패는 재시도가 가능하고, 쓰기 작업은 해당 요청의 읽기 캐시를 비웁니다.
- 네트워크 오류와 실제로 존재하지 않는 정치인을 구분해 안내합니다.

권한별 분석 범위와 기존 디자인을 유지합니다. 이전 152의 푸터 이메일 조치도 포함됩니다.

## 검증 범위

제어된 동일 테스트 자료로 수정 전후 JSON 응답이 같은 것을 확인했습니다.
이 자료에서 저장소 호출은 17회 → 10회, 같은 국회의원 목록 조회는 4회 → 1회로 줄었습니다.
이는 테스트 자료의 호출 횟수이며, 실제 서비스의 초 단위 속도나 개선율을 뜻하지 않습니다.
공개·회원·관리자 응답 분리, 요청 간 최신 데이터 반영, 오류 처리,
병렬 시작 및 중복 상세 요청 방지를 검사했습니다.

기존 공개 사이트에서 오세훈·김민석 카드의 상세 진입을 확인했으며,
수정된 153의 실제 서버 응답 시간과 삼성인터넷·모바일 체감 속도는 배포 후 확인이 필요합니다.

## 적용

- 152 사용 중: 153 PATCH ZIP을 같은 경로에 덮어쓴 뒤 배포합니다.
- 151·이전 진단 버전 사용 중: 153 전체 ZIP 하나로 교체합니다.
- 전체 ZIP을 적용했다면 PATCH를 추가로 적용하지 않습니다.
- 배포 후 기존 탭을 닫고 새 탭에서 메인 → 정치인 상세 → 뒤로가기 → 다른 정치인을 확인합니다.
- 회원과 관리자에서는 즐겨찾기 표시와 각 권한의 분석 항목도 확인합니다.

재수집, Redis 데이터 이전, APK 재빌드는 이번 웹 수정에 필요하지 않습니다.
