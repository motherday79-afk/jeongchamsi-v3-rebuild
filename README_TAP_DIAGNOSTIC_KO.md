# 삼성인터넷 연결 프로그램 창: 원인 확인용 패치 R2

이 파일은 연결 프로그램 오류를 해결했다고 주장하는 수정본이 아닙니다.
기존 JCS_0_0_31_151에 선택적으로 켜는 진단 기능을 추가했습니다. R2는 같은 기기·같은 버튼에서 복사 제한의 적용 여부만 비교할 수 있게 합니다.

첫 진단에서 더보기의 `span.when-closed → summary → details`에 pointerdown/up이 도달하고, 링크와 내부 이동 경로는 없었으며, 뒤따르는 click/toggle이 기록되지 않았습니다. 반복된 pointercancel만으로는 오류라고 판단할 수 없습니다. 복사 제한 또는 삼성인터넷 자체가 원인이라는 사실은 아직 입증되지 않았습니다.

## 적용

- 현재 사이트에 `JCS_TAP_DIAGNOSTIC_R2_20260913_PATCH.zip`을 풀어 같은 경로에 덮어쓴 뒤 배포합니다. 일반 151 또는 기존 진단 R1에 적용할 수 있습니다.
- 전체 파일이 필요하면 `JCS_0_0_31_151_DIAGNOSTIC_R2.zip`만 사용합니다. 두 ZIP을 모두 적용할 필요는 없습니다.
- 디자인, 게시글, 정치인 데이터, 일반 접속의 기존 클릭 동작은 바꾸지 않습니다.
- APK 재빌드 없이 배포된 웹사이트에서 사용할 수 있습니다.

## 문제 기기에서 확인

1. 배포가 끝나면 문제가 발생하는 삼성인터넷 주소창에 아래 주소를 직접 붙여넣습니다.

   `https://www.jeongchamsi.com/person/metropolitan-001?jcs_tap_debug=1`

2. 왼쪽 아래에 **터치 진단 R2** 버튼이 보이는지 확인합니다. R2가 없으면 새 진단 파일이 반영된 상태인지부터 확인해야 합니다.
3. 원래 설정에서 문제가 발생했던 **이슈 더보기 등 더보기 버튼을 한 번** 누릅니다. 연결 프로그램 선택창이 뜨면 앱을 선택하지 않고 뒤로가기로 그 창만 닫습니다.
4. **터치 진단 R2 → 복사 제한 제외 테스트 시작**을 누릅니다. 진단 창은 자동으로 접힙니다.
5. **같은 더보기 버튼을 다시 한 번** 누릅니다. 이번에도 선택창이 뜨면 그 창만 닫습니다.
6. **터치 진단 R2 → 결과 복사**를 눌러 결과를 보내고, 제한을 제외했을 때 더보기가 정상적으로 펼쳐졌는지도 알려주세요. 가능하면 버튼까지 이동한 후 불필요한 추가 스크롤 없이 두 조건을 비교합니다.
7. **진단 종료**를 누릅니다. 테스트에서 제외했던 복사 제한도 원래대로 복원됩니다. 패널의 **원래 복사 제한으로 복원** 버튼으로 먼저 복원할 수도 있습니다.

홈에서도 확인하려면 `https://www.jeongchamsi.com/?jcs_tap_debug=1`로 접속해 같은 순서를 따릅니다.
일반 주소에서는 진단 코드를 내려받거나 실행하지 않습니다. 이 테스트는 현재 페이지의 `#app`에 기존 복사 허용 예외를 잠깐 적용하므로, 같은 문서 안에서 내부 메뉴를 이동하는 동안은 유지됩니다. 새 페이지를 완전히 불러오거나 새 탭으로 옮기면 해당 진단 주소로 다시 접속해야 하며 테스트 조건은 원래 설정으로 시작합니다.
현재 페이지에서 진단을 종료한 뒤 같은 진단 주소로 새로고침하면 다시 켜집니다.

## 기록하는 내용

- pointerdown/up/cancel, click, 클릭 처리 뒤 상태, 펼침/접힘(toggle), contextmenu 및 기존 코드의 취소 여부
- 실제 이벤트 대상의 태그와 CSS 클래스, 터치 지점의 요소 겹침
- 링크 종류와 정참시 내부 경로, 앱의 내부 이동 요청
- 브라우저 버전과 화면 크기
- 이벤트가 발생할 때의 조건: 원래 설정 / 복사 제한 제외

입력창의 값, 비밀번호, 쿠키, 저장소, 페이지 본문은 읽지 않습니다. URL의 검색 조건과 해시, 외부 주소의 경로, 메일·전화 주소도 생략합니다.
최근 20개 이벤트만 현재 페이지 메모리에 보관하며 서버로 보내거나 자동 공유하지 않습니다. 결과 복사 버튼은 사용자가 직접 눌렀을 때만 작동합니다.
관찰 코드는 기존 이벤트를 취소하거나, 메일 링크를 막거나, 브라우저의 이동·공유 함수를 바꿔 끼우지 않습니다. R2는 실제 페이지를 터치하는 동안 기록을 메모리에만 쌓고, 사용자가 진단 결과를 열거나 복사할 때 화면을 갱신합니다.

**복사 제한 제외 테스트 시작**을 직접 누를 때만, 현재 페이지의 텍스트 선택·복사·길게 누르기 제한에 기존 예외를 적용합니다. 원래 설정 비교와 제외 설정 비교를 모두 R2에서 해야, 진단 자체 변경의 영향을 복사 제한의 영향으로 오인하지 않을 수 있습니다.

## 결과 해석과 한계

- `링크 mailto:[주소 생략]`이면 실제 메일 링크를 터치한 것으로 기록된 것입니다. 같은 지점의 겹침 정보와 함께 원인을 확인합니다.
- `대상 summary`, `링크 없음`, `경로 없음`이면 주소 이동용 링크가 아닌 펼침 요소에서 이벤트가 발생한 것입니다.
- `요청 /person/...`은 정참시의 내부 이동 요청입니다. 이 기록만으로 외부 앱 호출을 입증하지는 못합니다.
- 클릭 기록 없이 연결 프로그램 창이 나타나거나, 내부 이벤트만 정상적으로 기록되어도 브라우저 또는 다른 계층의 동작은 별도 확인이 필요합니다.
- 원래 설정에서는 문제가 반복되고 제한을 제외할 때만 정상 동작한다면, 복사 제한 기능과 증상의 관계를 다음 수정 근거로 삼을 수 있습니다. 어느 CSS 속성 또는 이벤트 처리 하나가 원인인지는 추가로 구분해야 합니다.
- 웹페이지는 Android가 실제 외부 앱에 전달한 Intent를 직접 읽을 수 없습니다. 따라서 이번 결과만으로 모든 경우의 원인이 확정되는 것은 아닙니다.

자동 검증은 진단 기록·주소 생략·관찰 코드의 기존 이벤트 비간섭과, 실제 기존 복사 제한 처리기의 예외 적용 및 복원을 확인합니다. R2의 삼성인터넷/갤럭시 실기 비교와 진단 패널 시각 확인은 아직 남아 있습니다.

## 제거

진단이 끝나면 일반 151의 `index.html`로 복원하고 `src/ui/tap-diagnostics.js`를 제거할 수 있습니다.
이후 기능 수정본을 배포할 때도 진단을 기본 기능으로 남기지 않습니다.
