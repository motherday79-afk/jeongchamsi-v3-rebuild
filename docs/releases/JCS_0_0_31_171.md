# JCS_0_0_31_171 — 관리자 승인형 모임

이 파일은 WEB170에 이어 적용하는 모임 기능 패치 안내입니다. 기존 배지, 정참시 로고, 케이지, 캠페인, 배너 자산은 유지합니다. 웹 소스 패키지이며 APK 파일이 아닙니다.

## 적용 범위

- 더보기와 전체 서비스 메뉴의 **모임** 아이콘 → `/groups`
- 관리자 메뉴의 **모임 관리** → `/groups?view=manage`
- 모임 둘러보기, 분야·검색·페이지 이동, 내 모임과 새 소식
- 회원의 모임 개설 신청 → 사이트 관리자 승인/반려 → 운영 시작
- 모임 가입 신청 → 모임장·운영진 승인/반려, 탈퇴·신청 취소
- 모임별 모임장 / 운영진 / 모임원 권한. 사이트 전체 회원등급은 변경하지 않습니다.
- 일반 글, 갤러리, 댓글, 공지, 일정과 참석/불참, 초대 링크
- 작성자는 자신의 글을 수정합니다. 운영진은 타인의 일반 글을 대신 고쳐 쓰지 못하며, 숨김·삭제 시 사유를 남깁니다. 공지는 운영진이 관리합니다.
- 모임장 위임, 운영진 지정/해제, 회원 내보내기, 모임 종료
- 공개 / 모임원 전용 / 초대 전용. 비공개 본문과 사진은 서버에서 가입 권한을 확인합니다.
- 이름·분류 변경은 재승인 대상입니다. 심사 중에는 모임장과 사이트 관리자만 상세를 볼 수 있습니다. 기존 모임원은 내 모임에서 참여를 취소할 수 있습니다.
- 종료된 모임은 내용을 읽을 수 있으며 작성·운영 변경과 새 소식 발행은 멈춥니다. 회원의 탈퇴는 가능합니다.
- 실제 푸시 발송은 포함하지 않습니다. 내 모임의 새 소식 및 모임별 수신 설정만 제공하며, 향후 푸시를 연결할 때 별도 동의와 발송 처리가 필요합니다.

## 적용 방법

1. 현재 운영 소스를 백업합니다.
2. WEB170에서 업데이트할 때는 PATCH ZIP의 파일을 프로젝트 루트에 덮어씁니다. 전체 소스가 필요할 때는 FULL ZIP을 사용합니다. 두 파일은 같은 171 결과물입니다.
3. 기존 Redis 연결 및 로그인 세션 환경변수는 유지합니다. 모임 데이터는 `jcsr2:groups:v1:*` 별도 키에 저장되어 기존 회원·배지·게시판 데이터와 구분됩니다. 별도 이관 명령은 없습니다.
4. 실제 대표 사진·갤러리 업로드를 사용하려면 아래 이미지 저장소 설정을 추가합니다.
5. 기존 웹 배포 절차로 배포한 뒤 버전 `JCS_0_0_31_171`과 아래 점검 항목을 확인합니다.

이 패키지 생성만으로 운영 사이트에 배포되지는 않습니다. GitHub / Vercel의 운영 데이터나 설정을 변경하지 않았습니다. 서버를 바라보는 기존 Android 앱이라면 웹 기능 반영을 위한 APK 재빌드는 필요하지 않지만 앱에서의 표시·탐색은 배포 후 확인해야 합니다.

## 실제 이미지 업로드 설정

회원 전용 사진이 공개 URL로 노출되지 않도록 **Private Vercel Blob 저장소**를 사용합니다.

- 저장소의 접근 유형을 **Private**으로 생성합니다.
- 해당 저장소의 서버용 Read/Write 토큰을 `JCS_GROUPS_BLOB_READ_WRITE_TOKEN` 환경변수에 설정하고 재배포합니다.
- 기존 배너·정치인 사진용 공개 `BLOB_READ_WRITE_TOKEN`은 그대로 유지합니다. 공개 저장소 토큰을 새 변수에 복사하는 것으로 비공개 저장소가 되지는 않습니다.
- 토큰은 브라우저 코드·ZIP·화면에 넣지 않습니다.
- 설정 전에도 예시 화면, 신청·승인, 글·댓글·일정은 이용할 수 있습니다. 실제 사진 업로드는 저장소 연결 안내를 표시합니다.

실제 업로드: JPEG / PNG / WebP, 파일당 최대 2MiB, 게시글당 최대 6장. SVG·GIF는 받지 않습니다. 사진 URL은 `/api/v3/groups?id=...&imageId=...`를 통해 매번 접근 권한을 확인합니다. 사진을 숨기면 운영진만 확인하며, 삭제·첨부 해제 후에는 해당 게시물에서 사진을 읽을 수 없습니다. 이미 열어 보거나 내려받은 사본을 회수하는 기능은 아닙니다.

Vercel 공식 설정 문서: https://vercel.com/docs/vercel-blob/using-blob-sdk

## 첫 적용 후 확인

- 더보기 → 모임: 예시 3개와 읽기 전용 안내, 글·갤러리·일정 표시
- 일반 계정: 새 모임 신청 후 공개 목록에 나타나지 않는지 확인
- 관리자: 모임 관리에서 승인, 일반 계정: 가입 신청 및 모임장의 승인
- 다른 계정: 승인 전에는 모임원 전용 본문·사진을 볼 수 없는지 확인
- 모임원: 일반 글·댓글·사진 업로드, 운영진: 공지·일정·참석 집계
- 숨김/삭제/내보내기/탈퇴 뒤 직접 사진 주소와 뒤로가기에서 접근이 남지 않는지 확인
- 두 창에서 같은 글을 편집: 충돌 시 입력 보존 및 최신 내용 확인 후 재저장
- 휴대전화와 PC에서 메뉴·카드·갤러리·입력창 표시 확인

## 검증 범위와 운영 한도

권한·승인·동시 저장·비공개 사진·예시 분리·실제 앱 모듈 연결에 대한 Node 자동 검사를 포함합니다. Redis 저장 시에는 비교 후 교체(CAS)를 사용하여 동시 수정의 무조건 덮어쓰기를 막습니다. Lua 스크립트 실행도 로컬 Lua 환경에서 점검했습니다. 실제 운영 Redis/Blob에 쓰거나 실기기 브라우저를 조작한 검증은 하지 않았습니다.

1차 모임별 JSON 저장 크기는 1MiB, 등록 이미지 메타데이터는 500개 한도입니다. 한도 초과 시 기존 데이터를 덮어쓰거나 삭제하지 않고 저장을 거절합니다. 운영 기록은 모임별 최근 200건을 표시·보관합니다. 대규모 장기 운영을 위한 게시물/이력 분할 저장과 미사용 이미지 정리 작업은 별도 확장 범위입니다. 사진 삭제는 노출 중단을 보장하며 저장소 원본의 영구 삭제 배치는 포함하지 않습니다.
