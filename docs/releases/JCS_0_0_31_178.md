# JCS 0.0.31.178 — 활동 포인트

177의 개별 정치인 갱신·24시간 심층 분석 권한을 유지하면서 일반 회원 활동으로 포인트를 모을 수 있도록 추가한다.

## 기본 운영값
| 구분 | 기본값 |
| --- | --- |
| 새 게시글 | 100P |
| 새 댓글 | 50P |
| 하루 합산 적립 | 최대2,000P, 한국시간 자정 초기화 |
| 적립 최소 분량 | 본문50자 / 댓글15자 (공백·기호·주소 등 제외) |
| 새 글·댓글 작성 간격 | 30초, 회원별 공통 |

활동 적립 포인트는 충전 포인트와 합산해 정치인 갱신·24시간 심층 분석 개방·케이지 개설에 쓸 수 있다. 상품 가격이나 충전 보너스는 변경하지 않는다. 기존 작성물에 소급 지급하지 않는다.

## 대상과 제외
커뮤니티·잇츠미 새 게시글, 커뮤니티·잇츠미·칼럼·뉴스 댓글, 실제 승인 모임의 일반 게시글·갤러리 본문·댓글을 대상으로 한다. 케이지 내 참여 글·댓글도 대상이다. 관리자 작성·예시 데이터·모임 공지/일정·유료 케이지 개설 자체·문의/신청은 제외한다.

짧지만 정상적인 내용은 작성할 수 있으나 적립하지 않는다. 점·공백·단독 자모·반복 문자로 분량을 채워도 인정하지 않는다. 같은 회원의 동일 본문은 띄어쓰기/기호를 바꾸거나 다른 게시판에 올리거나 삭제 후 재작성해도 중복 적립하지 않는다. 유사한 정치 주제를 다룬다는 이유로 제재하지 않는다.

## 회원 사용법
1. 로그인 후 커뮤니티·잇츠미·실제 모임에서 글이나 댓글을 작성한다. 작성 전 현재 지급 기준과 오늘 적립량을 확인할 수 있다.
2. 등록 후 적립액 또는 제외 사유를 확인한다. 작성 간격 제한과 저장 실패 시 입력은 유지된다. 결과를 확인하지 못한 요청은 같은 내용으로 재시도한다.
3. **마이페이지 → 포인트** 또는 충전소에서 잔액·오늘 적립·회수 예정 차감분·활동 내역을 확인한다.
4. 보유 포인트로 정치인 상세 상단의 **갱신하기**를 이용하거나 케이지를 개설한다.178에서 가격은 변경하지 않았으며, 실제 차감액은 해당 기능에서 안내한다.177의 정치인별24시간 심층 분석 열람·다중 비교 권한도 유지한다.

하루 남은 한도가 게시글/댓글 기본 적립액보다 적으면 잔여분까지만 적립한다. 회수분 차감에 사용된 신규 적립도 그날의 총 적립 한도에 포함된다.

## 삭제와 회수
본인이 작성물을 삭제하면 해당 적립을 취소한다. 부모 글 삭제로 함께 지워지는 본인 작성 글·댓글의 적립도 회수한다. 회수해도 그날의 적립 한도는 복구하지 않는다. 다른 사람의 정상 댓글이 부모 글 삭제에 따라 사라진 경우 자동 회수하지 않는다. 모임장의 단순 숨김/삭제는 사이트 관리자의 부정 적립 판정으로 취급하지 않는다.

미사용 활동 포인트부터 회수하며 부족분은 이후 활동 적립에서 차감한다. 이로 인해 충전 포인트나 충전 보너스를 차감하거나 지갑 잔액이 음수가 되지 않는다. 화면에서 실제 입금된 적립액과 회수 상계액을 구분한다.

## 관리자 사용법
관리자 로그인 → 관리자 메뉴의 **활동 포인트**에서 기본값과 적립 활성화를 설정한다. 직접 경로는 `/points?view=activity`이며, 설정 변경 사유를 함께 입력한다. **회원관리 → 해당 회원의 포인트 관리**에서 활동 내역을 확인한다. 의심 목록의 회원 보기로도 이동할 수 있다. 적립 내역에서 회수 사유를 입력하거나, 적립 제한 기간을 지정/해제한다. 제한 기간은 최대720시간(30일),0시간은 해제다. 적립 제한 기간에도 정상적인 글·댓글 작성은 가능하며 해당 활동에는 포인트가 지급되지 않는다. 의심 내역은 검토 자료이며 신고만으로 자동 회수하지 않는다. 운영 변경은 담당 관리자와 사유를 기록한다.

## 검증 및 실행 범위
- 전체 `npm test`:464개 통과,실패0,건너뜀0. 실제 gateway를 불러오는 배포 추적 검사 포함.
- 서버 권한과 원자적 저장, KST 자정, 동시 요청/한도, 정규화 중복, 본인 삭제 및 연쇄 삭제, 회수 후 재적립, 충전분 보호, 기존24시간 분석 권리와 유료 갱신 연동을 검증했다.
- 회원/관리자 렌더링과 조작, 요청 식별자, 계정 변경, 화면 이동 후 안내, 기존 케이지 진입과 입력 보존을 검사했다.
- 브라우저 화면 및 실제 Redis 서버에서의 실행 검증은 하지 않았다. 화면 검증 범위는 렌더러/이벤트 동작 검사와 스타일 소스 확인이며, Redis 경계는 제어된 저장소 모델과 Lua 코드 검토를 사용했다.
- 라이브 배포·데이터 수집·실제 회원 포인트 변경·결제는 수행하지 않았다.
- 중복 방지 해시와 거래/감사 기록은 보존한다. 장기 운영에 따른 기록 보관·아카이브는 별도 운영 과제다.
