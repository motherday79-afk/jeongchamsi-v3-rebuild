# JCS_0_0_31_175 — 인물별 지정 검색어·개별 갱신·포인트

기준 버전: JCS_0_0_31_174. 현재 작업 디렉터리에서 수정했으며 운영 배포·운영 DB 수집은 실행하지 않았습니다.

## 배포 및 전북 박지원 시험

174를 적용 중이면 PATCH ZIP을 압축 해제해 같은 경로에 덮어씁니다. 전체 교체할 때는 전체 ZIP만 사용합니다. 두 ZIP을 연달아 적용할 필요는 없습니다.

1. 관리자 → 정치인정보 → ‘박지원’ 검색 → 전북 군산시김제시부안군을(assembly-211)을 선택합니다.
2. ‘이 인물의 수집 검색어’에서 지정 검색어 기본값을 확인합니다. 검색량: 전북박지원, 군산박지원, 김제박지원, 부안박지원. 뉴스: 박지원 AND (전북 OR 군산 OR 김제 OR 부안).
3. ‘한 명만 수집·게시’의 ‘새로 수집’을 누릅니다. 키워드별 PC·모바일 수치와 수집 기사 목록을 확인합니다.
4. ‘게시’를 누르면 이 인물의 상세 자료와 NOW 순위가 함께 갱신됩니다. 다른 인물은 다시 수집하지 않습니다. 페이지를 다시 연 경우 ‘최근 수집 결과 확인’ 후 게시할 수 있습니다.

설정은 순위 번호가 아닌 인물 ID에 연결됩니다. assembly-026 전남 박지원의 수집 조건은 바뀌지 않습니다. 동일 ID의 인물 이름·관할 지역이 다른 경우에는 기본 시범 설정을 자동 적용하지 않습니다.

지정 키워드에서 확인된 수치만 순위에 반영하며, 미확인·10건 미만을 정확한 0건으로 표시하지 않습니다. 상세/비교에는 ‘지정 검색어 · 확인된 검색량 합계’라는 기준이 표시됩니다. 지역 조건으로 거른 RSS에 정상적으로 0건이 나오는 경우도 게시 가능합니다. API 장애와 정상 0건은 구분합니다. 기존 혼합 뉴스 이력은 새 조건에 합쳐지지 않습니다. 이름 수집을 계속하는 다른 인물의 기존 일별 이력은 유지합니다.

지역명이 포함된 동명이인 기사까지 완벽하게 식별하는 것은 아닙니다. 관리자 기사 확인과 기존 뉴스 오탐 제외 기능을 함께 사용합니다. 뉴스 조건 확인은 RSS 제목·설명 기준입니다.

## 회원 포인트 갱신

- 관리자 → 데이터수집·게시 → ‘회원의 정치인 개별 갱신’에서 이용료와 같은 인물의 재갱신 간격을 저장합니다.
- 기본값은 비활성, 이용료 미지정, 재갱신 간격 10분입니다. 활성화하려면 1~1,000,000P의 정수 이용료를 입력해야 합니다. 간격은 1~1,440분입니다.
- 활성화 후 로그인 회원의 정치인 상세페이지에 비용·보유 잔액·갱신 버튼이 나타납니다. 기존 포인트 충전과 잔액을 사용합니다.
- 수집과 공개 게시가 모두 성공할 때만 서버에서 정한 비용을 차감합니다. 인물 자료·순위·포인트 차감·사용 기록이 같은 원자적 저장으로 반영됩니다.
- 같은 요청의 재전송은 재차 수집하거나 차감하지 않습니다. 통신 응답이 불확실하면 같은 요청 번호로 ‘처리 상태 확인’을 사용합니다. 실패·시간 초과 시 차감하지 않습니다.
- 마이페이지·포인트 상점·관리자 회원 포인트 내역에 ‘정치인 갱신 · 이름’이 표시됩니다.
- 갱신 비용은 자료 재수집 비용이며 분석 열람 권한을 올려주지 않습니다. 결과는 해당 인물의 공개 자료에 반영됩니다. 수집처 갱신 주기에 따라 직전 수치와 같을 수 있습니다.

## 저장·게시 보호

개별 갱신은 현재 공개된 뉴스/검색 가중치를 사용합니다. 관리자가 바꾼 다음 전체 게시용 가중치를 개별 요청으로 임의 적용하지 않습니다. 다른 인물의 수집 입력은 유지하며, 상대 순위는 새 입력에 맞게 다시 계산됩니다. 개별 갱신은 동시점 전체 추세 측정이 아니므로 해당 계산으로 급상승을 만들지 않습니다.

전체 게시 중에는 개별 게시를 잠시 막습니다. 완료된 전체 게시 요청의 재전송은 공개 순위를 다시 쓰지 않습니다. 오래된 전체 수집본을 게시할 때에는 더 최근에 개별 게시한 자료를 유지하며, 그 인물이 전체 수집에서 실패했던 경우도 포함합니다. 갱신 초안은 인물당 한 자리로 교체하여 무제한 버전 누적을 방지합니다.

## 검증 범위

자동 검증에는 실제 HTTP 핸들러의 권한·가격 검사, 개별 수집/게시, 키워드·뉴스 필터, 0건 처리, 동시 게시, 중복 과금, 잔액 변경, 통신 오류 UI 복구, 기존 기능 회귀 및 배포 추적 검사를 포함합니다. 실제 운영 자격증명으로 API를 호출하거나 사용자 포인트를 차감하지 않았습니다. 실제 수집 결과와 순위 변화는 배포 후 위 절차로 확인합니다.
