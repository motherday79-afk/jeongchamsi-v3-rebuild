# JCS 0.0.31.9 비교·검증·선거데이터 핫픽스 실행계획

## 목표

- 상세페이지의 진단 01~10 시각화 계약을 비교하기에서도 동일하게 사용한다.
- 비로그인·회원·관리자 권한별 노출 범위와 인원 제한을 유지한다.
- D02, D04의 깨진 시각화와 D09 정책 오분류를 고친다.
- 공식 선거 데이터가 주입되면 D05·D08이 같은 값을 사용하도록 연결한다.
- 수집 검증 오류가 실제 결함을 가리키되 삭제된 레거시 문구 때문에 오탐하지 않게 한다.
- 관리자 화면에 배포 버전과 스냅샷을 표시하고 주요 카드 호버를 통일한다.

## TDD 순서

1. 비교 화면이 레거시 서술 필드를 출력하지 않고 `display` 계약을 쓰는 테스트를 추가한다.
2. D02 5개 연령대·성별 100% 구성과 D04 코어/유동/이탈 3개 원 테스트를 추가한다.
3. D09 비정책 기사 제외와 공식 선거 데이터 연결 테스트를 추가한다.
4. 이벤트 부재 fallback 및 검증 오류 유형별 회귀 테스트를 추가한다.
5. 관리자 버전 표시와 호버 CSS 테스트를 추가한다.
6. 최소 구현 후 대상 테스트, 전체 테스트, 문법 검사를 실행한다.
7. 변경 파일만 manifest와 함께 PATCH ZIP으로 묶고 ZIP 내용을 재검증한다.

## 구현 원칙

- 수치나 선거 결과를 임의 생성하지 않는다.
- 상세와 비교는 동일한 진단 `display` 데이터를 렌더링한다.
- 선거 데이터는 공식 데이터 레코드만 정규화하며 매칭되지 않으면 명확한 빈 상태를 유지한다.
- 검증은 화면에서 실제 사용하는 필드와 출처 일치성을 검사한다.
- 기존 미완성 변경과 사용자 파일은 삭제하거나 되돌리지 않는다.
