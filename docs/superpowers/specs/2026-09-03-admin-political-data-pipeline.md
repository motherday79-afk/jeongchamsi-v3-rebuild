# JCS 관리자 정치 데이터 수집·게시 파이프라인 설계

## 목표

정참시 관리자에서 운영자가 `전체 수집`과 `전체 게시`를 각각 한 번만 눌러 국회의원 300개 슬롯, 광역단체장 16명, 기초단체장 227명 등 총 543개 슬롯을 관리하고, 공석 1개를 제외한 실제 정치인 542명의 원자료 수집, JCS 분석, 검증, 게시를 완료한다. 최초 데이터 구축과 이후 새로고침은 같은 파이프라인을 사용한다.

## 변경 금지 조건

- 과거 542명 전체 데이터를 한 번의 `MGET`으로 읽어 Upstash 단일 요청 제한 10,485,760바이트를 초과했던 오류를 반복하지 않는다.
- 수집·분석·저장·검증·게시의 정치인 배치는 항상 25명 이하다.
- 전체 정치인 키를 한 번의 `MGET`으로 읽는 코드를 만들지 않는다.
- 관리자 조작은 `전체 수집` 한 번과 `전체 게시` 한 번으로 유지한다.
- 작업 상태를 Redis에 저장하고 새로고침, 네트워크 단절, 함수 종료 후에도 완료된 배치 다음부터 재개한다.
- 일부 대상의 실패가 나머지 대상의 진행을 중단시키지 않는다. 실패 대상과 단계, 오류코드, 재시도 횟수를 기록한다.
- 게시 도중 기존 공개 데이터는 변경하지 않는다. 새 스냅샷 전체 검증이 끝난 뒤 공개 포인터 한 개만 전환한다.
- 이 조건은 구현 편의를 이유로 임의 변경하지 않는다. 변경하려면 운영자의 사전 승인이 필요하다.

## 허용 데이터 원천

수집기는 아래 네 범주만 사용한다.

1. 네이버 검색광고 API의 PC·모바일 월간 검색량
2. Google 뉴스 웹/RSS 수집 결과. 네이버·다음 뉴스는 별도 API 없이 웹에서 확보될 때만 허용한다.
3. 한국갤럽과 중앙선거여론조사심의위원회 공개자료
4. 선거·인구·연령×성별 공식자료

네이버 검색광고 외 신규 유료·인증 API를 추가하지 않는다. 허용 범주 밖의 데이터를 대신 가져오는 fallback을 만들지 않는다. 원자료와 JCS 파생값에는 각각 출처, 수집시각, 수집방식, 산식 버전을 기록한다.

## 네이버 검색광고 연결

서버 전용 Production 환경변수 이름은 기존 버전과 동일하게 유지한다.

- `NAVER_AD_ACCESS_LICENSE`
- `NAVER_AD_SECRET_KEY`
- `NAVER_AD_CUSTOMER_ID`

클라이언트로 값을 내려보내거나 로그에 출력하지 않는다. `/keywordstool` 읽기 요청만 사용하며, 서명은 `{timestamp}.GET./keywordstool` 문자열을 Secret Key로 HMAC-SHA256 처리한 뒤 Base64로 인코딩한다. 서버는 `X-Timestamp`, `X-API-KEY`, `X-Customer`, `X-Signature` 헤더를 전송한다.

기존 Vercel 프로젝트 `jeongchamsi-v3-preview-clean`은 읽기만 허용한다. 현재 연결된 계정에서 기존 프로젝트가 조회되지 않으므로, 새 프로젝트에 키가 이미 존재하는지 확인하고 없을 때는 운영자가 Vercel Production 환경변수에 직접 입력한다. 키 값은 채팅이나 코드, ZIP에 포함하지 않는다.

## 데이터 모델

### 작업 상태

작업은 `collect`와 `publish` 두 종류다. 각 작업은 다음 상태를 가진다.

- `IDLE`, `RUNNING`, `COMPLETED`, `COMPLETED_WITH_ERRORS`, `FAILED`
- 작업 ID와 스냅샷 ID
- 전체·완료·성공·실패 대상 수
- 현재 배치 시작 위치와 마지막 완료 대상
- 단계별 시작·종료 시각, 예상 남은 시간
- 대상별 재시도 횟수와 오류 기록

동시에 같은 종류의 작업이 중복 실행되지 않도록 Redis 잠금을 사용한다. 만료된 잠금은 저장된 커서에서 안전하게 복구한다.

### 스냅샷

정치인별 데이터를 하나의 거대한 값으로 합치지 않는다.

- 원자료: 스냅샷·정치인·원천별 분리 키
- JCS 분석 초안: 스냅샷·정치인별 분리 키
- 게시본: 스냅샷·정치인별 분리 키
- 순위: 통합 TOP 30과 분야별 순위용 소형 인덱스 키
- 공개 포인터: 현재 공개 스냅샷 ID 한 개

공개 상세페이지는 공개 포인터를 읽은 뒤 해당 정치인의 게시본 한 건만 읽는다. 메인 NOW Rank는 카드에 필요한 값이 포함된 소형 TOP 30 인덱스만 읽는다.

## 수집 흐름

1. 관리자가 `전체 수집`을 누르면 새 스냅샷과 작업 상태를 만든다.
2. 공유 원자료인 한국갤럽·인구 자료를 먼저 한 번 수집하고 원본을 보존한다.
3. 543개 슬롯 중 공석 1개를 제외한 542명 ID 목록을 25명 이하 배치로 나눈다.
4. 각 정치인에 대해 네이버 PC·모바일 검색량, Google 뉴스, 선거·여론·인구 맥락을 수집한다.
5. 일시적인 네트워크·429·5xx 오류는 대상별 최대 3회 재시도한다.
6. 영구 오류는 해당 대상에 기록하고 다음 정치인으로 계속 진행한다.
7. 각 배치가 끝날 때 분석 초안과 작업 커서를 저장한다.
8. 관리자 화면은 저장된 작업 상태를 읽어 진행률, 현재 구간, 성공·실패, 예상 남은 시간을 표시한다.
9. 화면이 새로고침되면 진행 중인 작업을 감지하고 다음 미완료 배치부터 자동 재개한다.

브라우저는 배치 API를 순차 호출하는 실행 조정자 역할만 한다. 실제 수집·서명·분석·Redis 쓰기는 모두 서버에서 수행한다. 각 요청은 배치 하나만 처리해 Vercel 함수 시간 제한과 Upstash 요청 크기를 넘지 않는다.

## JCS 분석 원칙

- 원자료의 사실값과 JCS 해석·지수를 분리해 저장한다.
- 검색량, 기사 수, 선거 득표, 공식 인구처럼 사실인 숫자는 원자료에서만 가져오며 임의 생성하지 않는다.
- 관심도·확산력·활동성·미디어성·지속성·변동성, 연령×성별 관심 구조, 지지 구조, 위험·기회, 전략 등 JCS 파생값은 허용 원자료를 조합한 버전 고정 산식으로 모든 정치인에게 계산한다.
- 특정 정치인의 직접 여론조사가 없더라도 같은 허용 범주의 정당·지역·인구·선거·뉴스 자료를 결합해 `JCS 해석` 값을 계산한다. 허용 범주 밖 자료로 대체하지 않는다.
- 연령×성별 각 셀은 개별 입력 특징으로 계산한다. 하나의 스칼라를 모든 셀에 복제하지 않는다.
- 동일 인물의 모든 연령 또는 모든 성별 값이 완전히 같은 복제 벡터면 검증 실패로 처리하고 산식을 다시 실행한다.
- 산식은 결정적이어야 한다. 같은 스냅샷 원자료와 같은 알고리즘 버전은 항상 같은 결과를 만든다. 난수는 사용하지 않는다.

## 게시 흐름

1. `전체 게시`는 수집 작업이 종료되고 스냅샷 검증을 통과했을 때만 시작한다.
2. 정치인 초안을 25명 이하 배치로 읽고 게시 네임스페이스에 복사한다.
3. 분야별·통합 NOW 점수를 계산하고 실제 TOP 30 인덱스를 만든다.
4. 게시본의 총 대상 수, 필수 필드, 원자료 출처, 연령×성별 복제 오류, 순위 중복을 검증한다.
5. 하나라도 필수 검증에 실패하면 공개 포인터를 바꾸지 않는다.
6. 전체 검증이 성공하면 공개 포인터를 새 스냅샷 ID로 원자 전환한다.
7. 이전 공개 스냅샷과 Redis 데이터는 삭제하지 않는다.

## 관리자 화면

기존 회원·콘텐츠 요약을 유지하고 `정치 데이터 운영` 영역을 추가한다.

- 네이버 검색광고: 연결 여부만 표시하고 비밀값은 표시하지 않는다.
- 데이터 원천 네 범주의 연결 상태와 최근 성공 시각
- `전체 수집` 버튼 한 개
- 수집 진행률, 현재 배치, 완료·성공·실패, 예상 남은 시간
- 실패 대상 목록과 자동 재시도 결과
- 수집 완료 스냅샷의 검증 결과와 TOP 30 미리보기
- `전체 게시` 버튼 한 개
- 게시 진행률과 현재 공개 스냅샷

## API 경계

- `GET /api/v3/admin/intelligence/status`: 연결 상태, 진행 중 작업, 최신 초안·공개 스냅샷
- `POST /api/v3/admin/intelligence/collect/start`: 수집 작업 생성 또는 기존 미완료 작업 반환
- `POST /api/v3/admin/intelligence/collect/step`: 다음 25명 이하 배치 처리
- `POST /api/v3/admin/intelligence/publish/start`: 게시 작업 생성과 사전 검증
- `POST /api/v3/admin/intelligence/publish/step`: 다음 25명 이하 게시 배치 또는 최종 포인터 전환
- `GET /api/v3/admin/intelligence/preview`: 최신 초안의 검증 결과와 TOP 30

모든 경로는 서버에서 관리자 세션을 재검증한다. 작업 ID, 스냅샷 ID, 커서는 클라이언트 입력을 신뢰하지 않고 Redis 상태와 대조한다.

## 검증 기준

- 25명보다 큰 배치 요청을 서버가 거부한다.
- 542명 전체 키 단일 `MGET`이 코드 경로상 불가능하다.
- 배치 읽기는 최대 25개 키 단위로 수행된다.
- 중간 실패 후 다시 호출하면 완료된 대상은 재처리하지 않는다.
- 한 대상의 실패 후에도 다음 대상이 처리된다.
- 연령×성별 복제 벡터가 게시 검증을 통과하지 못한다.
- 부분 게시 실패 시 기존 공개 포인터가 유지된다.
- 전체 게시 성공 시에만 새 공개 포인터와 NOW TOP 30이 함께 노출된다.
- 비관리자와 비로그인 사용자는 관리자 수집·게시 API를 호출할 수 없다.
- 네이버 비밀값이 API 응답, 화면 HTML, 오류 메시지, 로그에 포함되지 않는다.
