# 활동 포인트 178 승인 명세

사용자는 게시글 100P, 댓글 50P, 하루 합산 2,000P와 부정 적립 방지 제안을 승인하고 구현을 요청했다. 활동만으로 모으기, 충전과 합산하기, 즉시 충전하기를 동등하게 지원한다. 가격이나 충전 상품은 변경하지 않는다.

## 적립과 범위
- 기본 enabled=true, postPoints=100, commentPoints=50, dailyLimit=2000, postMinLength=50, commentMinLength=15, cooldownSeconds=30. 하루는 한국시간 00:00 기준. 관리자가 변경 가능.
- 일반 활동: community/itsme 새 게시글, community/itsme/columns/news 댓글, 승인된 실제 모임의 일반 게시글·갤러리 본문과 댓글. 모임 공지/일정, 유료 케이지 개설 자체, 문의/신청, 관리자 작성, 예시/가상 데이터에는 적립하지 않는다. 케이지 내 일반 참여 글/댓글은 적립 대상이다. 활성 비관리자 회원(파트너의 일반 참여 포함) 대상.
- 수정/재저장/재시도는 추가 적립하지 않는다. 과거 작성물 소급 지급 없음. 클라이언트의 userId, 포인트, 일일 횟수는 신뢰하지 않는다.
- 적립 가능 분량은 NFKC 정규화 후 문자·숫자로 계산하되 HTML 태그·주소·공백·기호·이모지·단독 자모를 제외한다. 단순 같은 문자/짧은 구절 반복을 판별한다. 정상적인 짧은 의견은 작성 허용, 포인트만 제외.
- 동일 회원의 정규화된 동일 본문을 게시판/모임과 글·댓글 간에도 중복 비교한다. 삭제한 기록의 해시도 보존한다. 유사한 정치 주제 자체는 차단하지 않는다. 명백한 반복만 자동 적립 제외.
- 동일 회원의 성공한 새 글·댓글은 공통 최소 작성 간격 적용. 기본 30초. 간격 미달은 저장·적립 모두 하지 않고 재시도 가능 시간을 안내한다. 관리자 작성은 제외.
- 지급액이 당일 잔여 한도보다 많으면 잔여분까지만 지급한다. 회수·삭제로 당일 누적 적립 한도가 되살아나지 않는다. 회수 상계된 신규 적립도 총 적립액으로 한도에 포함한다.

## 저장과 회수
- 내용 저장과 적립 지갑·기록·제한 상태를 Redis CAS 한 번으로 처리한다. 모임 인덱스/회원 인덱스도 같은 커밋에 포함한다. 저장 실패/충돌이면 포인트만 지급되는 일이 없어야 한다.
- 충전/사용/개별 갱신과 동시 요청에도 지갑 변경, 24시간 분석 권리, 결제 요청이 보존된다.
- 같은 콘텐츠·요청에는 한 번만 지급하며 재시도는 이중 지급하지 않는다. 새 UI는 요청 식별자를 재사용한다.
- 본인 삭제 시 해당 작성물의 적립 회수. 다른 사람의 정상 댓글이 부모 삭제로 함께 사라지는 경우 해당 댓글 작성자에게 자동 제재하지 않는다. 그룹 운영자의 단순 숨김/삭제도 부정 판정으로 간주하지 않는다. 부정 적립 확정 회수는 사이트 관리자만 할 수 있다.
- activityCredit(미사용 활동 적립분)을 별도 추적한다. 갱신·케이지 사용은 활동 포인트부터 소진한다. 회수는 남은 활동 적립분에서 우선 차감하고, 부족분은 activityDebt로 기록하여 이후 활동 적립에서 상계한다. 충전 포인트와 충전 보너스는 이 상계로 차감하지 않으며 음수 잔액을 만들지 않는다.
- 삭제·관리자 회수는 중복 실행에도 한 번만 회수한다. 이미 회수된 원장을 보존한다.

## 운영/API/UI
- GET /api/v3/points의 기존 결과에 activityRewards 추가: {policy, day, earnedToday, remainingToday, debt, credit, restrictedUntil, restrictionReason}. wallet=1/member=...에도 제공. 관리자 status에는 activityAdmin:{policy,suspects,audit} 제공. 비관리자에게 운영 로그/타 회원 정보 비노출.
- POST points: activity-policy, activity-revoke, activity-restrict 관리자 전용. policy는 활성화/적립액/일일한도/최소길이/간격 검증; revoke는 userId,eventId,reason,requestId; restrict는 userId,hours(0=해제),reason,requestId. reason 필수, 최대 30일. 관리자 역할·정지 상태 서버 검증, 감사 로그.
- 글/댓글 등록 응답의 activityReward = {status,reason,earned,credited,offset,earnedToday,dailyLimit,remainingToday,retryAfterSeconds?}; 그룹은 응답 최상위, 일반은 새 item/comment에 응답 전용으로 전달. public content에는 다른 회원의 지갑/일일 적립량/제한을 저장하거나 노출하지 않는다.
- status: credited / excluded. reasons: awarded, minimum-length, repetitive, duplicate, daily-limit, restricted, disabled, ineligible. 에러 ACTIVITY_RATE_LIMIT에 retryAfterSeconds. 가능하면 공통 한글 메시지 모듈로 설명.
- 관리자 충전소에 활동 포인트 설정과 최근 의심 적립 목록, 회원별 적립 내역·회수·기간 제한. 명확한 제목/라벨/밝은 배경의 어두운 글자, 기존 퍼플·골드 유지.
- 회원 작성 전 적립 기준과 오늘 누적/한도 안내, 등록 후 적립/제외 사유 알림, 마이페이지/충전소의 적립·회수·상계 내역과 오늘 누적. 활동 포인트도 기존 갱신·24시간 분석·케이지에 합산 사용.
- 기존 디자인과 공개/모임 접근 권한을 유지하며 샘플은 계속 읽기 전용. 라이브 데이터 수집/배포/포인트 조작하지 않는다.

## 검증과 전달
- 핵심: 혼합 글/댓글, KST 자정, 병렬 한도·중복, 저장 실패, 수정/삭제 재등록, 점/기호/HTML/단어 반복, 권한 위조, 관리자 제외, 모임 CAS/사생활, 삭제 회수/이미 사용한 적립분/충전 보호, 운영 제한 및 사유, 갱신 권리 보존.
- 기존 전체 Node 테스트와 배포 추적, 177+178 패치=178 전체 ZIP 바이트 일치 확인. 신규 의존성 없음. 현재 디렉터리를 유지하고 Git 재체크아웃/리포 초기화하지 않는다.
- 실제 브라우저 확인은 기존 로컬 접근 차단을 우회하지 않는다. 못한 검증을 완료한 것으로 주장하지 않는다.
