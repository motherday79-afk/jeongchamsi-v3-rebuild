## Mutations and inputs
create {name(2..60),category,description(1..1500),region(<=80),rules(<=4000),visibility:'public'|'members'|'invite',privacyAccepted:true} -> status pending; group-specific membership pending until site approval; no picture needed at first. Cover upload available to applicant in settings after initial create.
review {decision:'approve'|'reject',reason(<=500)} site admin; rejection requires reason; approve activates owner.
settings {name,category,description,region,rules,visibility,coverImageId?} owner/admin. Name/category changes on approved group return to pending review; privacy changes immediate. Empty coverImageId removes cover.
resubmit {} rejected owner/admin -> pending.
close {reason} owner/admin -> closed readonly.
join {privacyAccepted:true} signed-in user; approved group only; invite token needed if invite-only. -> membership pending.
leave {} pending or active user except owner; removes active access and news subscription.
member {userId,decision:'approve'|'reject'|'remove'|'promote'|'demote',reason?} manager; promote/demote only owner/admin; moderators cannot affect owners or peers.
transfer {userId} owner/admin; active member becomes owner and previous owner becomes member.
post {postId? (update),title(1..120),body(<=10000),kind:'post'|'gallery'|'notice',imageIds:[id] (max6)} active members; notice only managers. Gallery >=1 image required. Only original author edits member post; managers edit other authors only for notices. UI renders plain text with escaped output, no user HTML.
post-delete {postId,reason?} own author or manager; manager deleting others requires reason; tombstone, no read exposure.
post-hide {postId,hidden:boolean,reason} managers, audit saved.
comment {postId,body(1..2000)} active members.
comment-delete {postId,commentId,reason?} author or manager; preserve audit.
event {eventId? (update),title(1..120),body(<=4000),startsAt:ISO,place(<=160)} managers.
event-delete {eventId,reason} managers.
rsvp {eventId,response:'yes'|'no'} active members; counts exclude removed/left members.
report {postId,body(1..1000)} active members; confidential to managers.
notify {enabled:boolean} active members; saves preference for in-app news/future push.
read {} active members; lastSeenAt server now.
invite-reset {} owner/admin; revokes previous invite link.

Errors: LOGIN_REQUIRED, GROUP_FORBIDDEN, GROUP_NOT_FOUND, GROUP_CONFLICT, GROUP_INPUT_INVALID, GROUP_REVIEW_REQUIRED, GROUP_EXAMPLE_READ_ONLY, GROUP_OWNER_TRANSFER_REQUIRED, GROUP_MEMBERS_ONLY, GROUP_INVITE_INVALID, GROUP_IMAGE_INVALID, GROUP_IMAGE_TOO_LARGE, GROUP_MEDIA_NOT_CONFIGURED, GROUP_LIMIT_REACHED, GROUP_STORAGE_FAILED. ## Final integration notes
- Summary additionally includes version and canLeave. Viewer includes canLeave, evaluated against actual owner ID regardless of global admin role.
- Leave returns {ok:true,item:{id,version,left:true}} and redirects to My Groups, because invite-only access may be revoked by leaving.
- Membership status also supports left. Pending/rejected detail is owner/admin only; My Groups still allows participation cancellation via summary version.
- Closed groups expose retained content but no content/management writes or unread notification. A member can leave through My Groups.
- Media is a dedicated Private Blob store via JCS_GROUPS_BLOB_READ_WRITE_TOKEN. JPEG/PNG/WebP <=2MiB, <=6 images/post, <=500 assets/group, group JSON <=1MiB.
- Newly uploaded unattached photos can be previewed by uploader/managers. Attached assets follow post visibility; deleted/detached asset URLs are denied.
- Membership data and real groups are separate from existing user ranks, badge engine, campaigns and their example records.
- Groups are excluded from HTML history snapshots to recheck access on browser Back.
- No live deployment, push sending, or physical-browser verification is claimed by the ZIP handoff.
