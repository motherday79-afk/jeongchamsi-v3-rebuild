JCS SELECTION CHECK R2 — 모바일 선택 설정 확인

이번 R1 결과: A 열림 / B 열림 / C 안 열림.
아직 원인을 확정하거나 서비스 전체에 수정을 적용한 파일은 아닙니다.

업로드
1. jcs-touch-check 폴더 안의 새 파일 3개를 기존 저장소의 같은 폴더에 추가합니다.
   selection.html / selection.mjs / selection-core.mjs
2. 배포 완료 후 문제가 있었던 휴대폰에서 아래 주소를 직접 엽니다.
   https://www.jeongchamsi.com/jcs-touch-check/selection.html

휴대폰에서
1. 아래쪽에 '1 · 선택 제한만 해제'가 나오면
   '제목 찾기'를 누르고 '나는 이렇게 제안합니다' 제목을 짧게 5번 눌러 보세요.
2. 메일 앱이 열리면 뒤로 돌아와 '메일 앱 열림'을 누릅니다.
   열리지 않으면 '안 열림'을 누릅니다.
3. 안 열렸던 경우 같은 화면에서 자동으로 '2 · 원래 설정'으로 전환됩니다.
   같은 제목을 다시 눌러 열림 여부를 기록합니다.
4. '결과 복사'를 눌러 대화에 붙여넣어 주세요.

두 조건 사이에는 폴드를 접거나 펼치거나 화면 확대를 변경하지 마세요.
원래 페이지의 디자인·앱 코드·이메일·링크는 그대로입니다.
변경하는 것은 body의 user-select와 같은 기능의 -webkit-user-select뿐입니다.
기존 '-webkit-touch-callout', 복사/우클릭 이벤트 코드도 유지합니다.

과거 복사 예외 테스트는 #app에 예외 속성을 추가했습니다.
이번 확인은 선택 금지가 남아 있던 body 자체의 설정을 변경합니다.
진단 주소에서만 적용되며 일반 이용자의 페이지에는 적용되지 않습니다.
설정 원복 및 클릭 유지 등 자동 테스트 5개를 통과했습니다.
자동 테스트는 안드로이드의 외부 앱 전환 현상을 재현한 테스트가 아닙니다.

판정
- 해제 시 안 열림 / 원복 시 열림: 해당 선택 설정과 증상의 관련성이 좁혀집니다.
- 해제해도 열림: 이 설정만으로는 설명되지 않습니다.
- 두 조건 모두 안 열림: 원래 조건의 재현이 없어 원인 확정 불가입니다.

진단 기록은 해당 브라우저의 sessionStorage에만 저장됩니다.
이메일 값·선택된 텍스트·입력값은 보고서에 기록하지 않습니다.
외부 앱 실행이나 네트워크 전송을 새로 추가하지 않습니다.
현재 서비스 버전 0.0.31.153의 스타일 및 앱 파일을 불러옵니다.

verification 폴더는 업로드할 필요가 없습니다.
검증: verification에서 npm install 후 npm test
