# JCS 0.0.31.162 — 공통 API 서버 배포 누락 수정

160에서 케이지 글씨 계산에 사용하는 공통 파일의 import 경로에 브라우저 캐시용 버전 문자열(?v=...)이 붙었습니다. 이 코드는 게시판 서비스를 거쳐 공통 API 서버에서도 사용됩니다.

Vercel의 파일 추적 도구(@vercel/nft 1.11.0)로 배포 파일 목록을 만들자 cage-brush-metrics.js가 누락됐습니다. 그 목록만 별도 폴더에 복사해 실행했을 때 공통 API가 ERR_MODULE_NOT_FOUND 오류로 시작하지 못하는 것을 확인했습니다. 따라서 해당 배포 묶음에서는 배너·게시글·정치인 순위 등의 API를 처리할 수 없습니다. 이전 161은 화면의 빈 배너 처리만 고쳤고 이 서버 시작 실패는 고치지 못했습니다.

162에서는 서버와 화면이 함께 사용하는 파일의 경로에서 버전 문자열을 제거했습니다. 변경된 화면 코드의 캐시 버전도 갱신했습니다. 서체·글씨 배치·로고·배지·캠페인·모든 기존 이미지와 데이터 파일은 유지합니다.

## 적용

- 현재 161 버전이면 JCS_0_0_31_162_PATCH.zip을 풀어 같은 경로에 덮어쓴 뒤 배포합니다.
- 전체 파일로 교체할 경우 JCS_0_0_31_162.zip만 사용합니다. 두 ZIP을 중복 적용하지 않습니다.
- 이 패치 적용에 데이터 초기화·재수집·배너 재등록·환경변수 변경은 필요하지 않습니다.
- 배포 후 /api/v3/health에서 JCS_0_0_31_162를 확인하고 메인의 기존 데이터 표시를 확인합니다.

## 검증

수정 전 배포 파일 목록과 별도 실행 환경에서 파일 누락 및 서버 시작 실패를 재현했습니다. 수정 후 같은 방식으로 새 배포 묶음을 만들었으며, 실제 API 코드를 통해 health·배너·케이지 게시글·정치인 순위 응답을 확인했습니다. 이때 외부 Redis 통신만 읽기 전용 검증 데이터로 대체했고, 저장된 검증 값은 변경되지 않았습니다. 운영 DB를 변경하거나 새 데이터를 주입하지 않았습니다.

동일한 결함을 잡는 tests/server-package.test.js를 추가했습니다. npm ci 후 npm test로 실행할 수 있습니다. @vercel/nft는 개발·검증 의존성으로만 추가했으며 기존 운영 의존성과 잠긴 버전은 변경하지 않았습니다. 검증 자료는 verification/api-package-162/에 포함했습니다.

실제 운영 사이트의 API 응답과 Vercel 로그는 현재 연결에서 직접 확인하지 못했습니다. 위 결론은 전달한 소스의 배포 파일 추적과 독립된 배포 묶음 실행을 근거로 합니다. 운영 배포는 수행하지 않았습니다.
